# Обзор проекта

## Проблема

Guardio и аналоги (Malwarebytes Browser Guard, Aura, Norton) решают реальные
задачи — фишинг, вредоносные расширения, мониторинг утечек, — но платят за это
приватностью пользователя: **URL посещённых страниц, IP, инвентарь устройства
уходят на сервер вендора и хранятся там персонализированно**. В админке Guardio
это видно буквально: журнал «Browsing Activity» на 203 события с пагинацией на
29 страниц отрисован из серверного хранилища (см.
[research/2026-08-02-guardio-teardown.md](research/2026-08-02-guardio-teardown.md), §2.2).

Плюс коммерческие раздражители: заблюренные «рекомендации» ради апсейла,
залоченный за пейволом выбор Google как поисковика, отсутствие триала и
3-дневное окно возврата.

## Цель

Свой продукт с тем же покрытием функций, но:

1. **История браузинга никогда не покидает устройство.**
2. Внешние проверки — только по анонимизированным примитивам (хэш-префиксы,
   k-anonymity, локальные Bloom-фильтры), сеть — только при попадании.
3. Никаких dark-pattern'ов и пейволов внутри собственного инструмента.
4. Детект не слабее, а местами сильнее Guardio за счёт проактивных фидов
   (Certificate Transparency, новые домены) и crypto-слоя.

## Принципы (нарушение = блокер на ревью)

| # | Принцип | Практическое следствие |
|---|---|---|
| P1 | Local-first | Журнал событий, инвентарь расширений, история вердиктов — только в локальном хранилище |
| P2 | Минимум сетевых запросов | Сначала локальный индекс/фильтр, сеть — только при попадании |
| P3 | Анонимные примитивы | Наружу уходят префиксы хэшей, не URL и не email в открытом виде |
| P4 | Без хранения чужих ПДн | Сырые дампы «email:пароль» не хостим (GDPR-риск), только хэши и метаданные |
| P5 | Самоаудит | Продукт показывает пользователю, какие запросы он сам сделал |
| P6 | Actionable > alarming | Очередь из 3 действий вместо счётчика на 203 алерта |
| P7 | Экспортируемость | Все данные пользователя выгружаются в JSON в один клик |

## Скоуп фич

Приоритет задан заказчиком 2026-08-03: **упор на безопасность в эпоху AI**.
Полное обоснование и механика — в [product-vision.md](product-vision.md).

### Must (ядро продукта)

1. **AI Shield** — скан страницы на вшитые скрипты и команды, адресованные
   AI-агентам (indirect prompt injection): скрытый в DOM текст, нерендеримые
   носители (комментарии, `meta`, `alt`, `aria-*`, JSON-LD), zero-width и
   Unicode-теги, императивы к модели, известные шаблоны кампаний.
   Три локальные ступени: DOM-vs-render diff → правила/сигнатуры → компактный
   ONNX-классификатор.
2. **Санитайзер и режим агента** — удаление скрытых инструкций из DOM до того,
   как их прочитает сайдбар/агент/суммаризатор; подтверждение перед
   чувствительным действием агента на заражённой странице.
3. **Guard ссылок и загрузок** — проверка URL до перехода (локальные фиды +
   Safe Browsing Local List + скоринг домена) и каждой загрузки
   (`chrome.downloads` + `onDeterminingFilename`, репутация `finalUrl`, тип
   файла, хэш по MalwareBazaar / опционально VirusTotal).
4. **Утёкшие пароли и данные** — офлайн-проверка по корпусу Pwned Passwords;
   мониторинг утечек по мультиисточнику, включая infostealer-логи.
5. **Extension Guard** — инвентарь, риск-скоринг, **дифф разрешений между
   версиями**, алерт о смене владельца, предупреждение до установки.
6. **Дружелюбный ассистент** — объясняет причину человеческим языком и доводит
   до починки: очередь из трёх дел, кнопки действий, авто-выполнение
   безопасных шагов. Деградация: плейбуки → локальная модель → Chrome Built-in
   AI (Gemini Nano) → опционально свой API-ключ. Содержимое страницы наружу по
   умолчанию не уходит.

### Should

- **Проактивный watchlist** — CertStream + фид новых доменов + typosquat вокруг
  брендов, которыми пользователь реально пользуется.
- **Diff-режим** — «что изменилось с прошлой недели».
- **Notifications control** — блокировка непрошеных push-уведомлений.
- **Search hijack detection** — детект подмены поисковика и цепочек редиректов.

### Could

- **Crypto/Web3-слой** — дрейнер-сайты и опасные `approve` (в инвентаре
  пользователя TronLink и Tonkeeper).
- **Проверка агентской обвязки** — устанавливаемые MCP-серверы и «скиллы»
  агентов как новый supply-chain вектор.
- **Email security** — разбор писем локально (IMAP; Gmail OAuth противоречит P1).
- **E2E-синк между своими устройствами** — сервер «слепой», ключ у пользователя.

### Non-goals

- Антивирус для файловой системы / лечение уже заражённого устройства.
- Кредитный мониторинг и страховка от кражи личности (привязаны к США).
- Продажа подписок, биллинг, мультиарендность — продукт бесплатный и открытый
  (движок — Apache-2.0, продукт — AGPL-3.0, ADR-0014), монетизации нет по
  решению Q2.
- Хостинг чужих breach-дампов и их перепродажа.
- Отправка содержимого страниц в облако «для анализа» — включая своё.
- Мобильные приложения на первом этапе.

## Ограничения платформы (Chrome MV3, 2026)

- MV2 отключён полностью; background — эфемерный service worker, долгие таймеры
  только через `chrome.alarms`.
- Блокировка через `declarativeNetRequest`: потолок ~330 000 статических и
  ~30 000 динамических правил. Публичные фишинг-листы (250k+) целиком в динамику
  не влезают → гибрид: статический пакет в билде + динамика для «горячих» +
  локальная проверка хэшей в service worker.
- `webRequestBlocking` недоступен → страница-предупреждение через
  `webNavigation.onBeforeNavigate` + редирект на свой интерстишл.
- Плюс к приватности: DNR-правила исполняются браузером, расширение не читает
  сами запросы.
- Локальный ML реалистичен: WebLLM/WebGPU либо ONNX/TF-Lite в SW.

## Что берём у Guardio (проверенные решения)

- Онбординг-прогресс «N/5 completed».
- Единый дашборд вместо разрозненных инструментов.
- Понятные теги утечек (`PASSWORD`, `EMAIL`, `IP ADDRESS`).
- Архив разобранных утечек (иначе список вечно красный).
- Предупреждение о расширении **до** установки.
- Несколько источников в мониторинге (email + телефон + «добавить ещё»).
