# Реестр источников данных

Рабочий реестр для реализации. Цены — ориентир на 2026-08, перед закупкой
перепроверять. Статусы: `выбран` / `кандидат` / `отклонён` / `не решено`.

Легенда приватности: ★★★ — наружу не уходит ничего идентифицирующего;
★★ — уходит анонимизированный примитив (префикс хэша); ★ — уходит plaintext
идентификатор (email/URL).

### 1.3 Ключевые выводы

1. **Infostealer-логи ≠ breach-дампы.** Свежие заражения (сессии, куки,
   автозаполнение) опаснее старых дампов. Guardio показывает их как
   «Available on the dark web» / «Source is hidden». Бесплатный источник —
   Hudson Rock Cavalier.
2. **Пароли проверяются полностью офлайн.** Корпус Pwned Passwords скачивается
   целиком → локальный индекс → ноль запросов о пароле (итог проверки уходит событием
   `check_done`, пока включены данные об использовании и ошибках). Это строго лучше, чем у
   Guardio.
3. **Стратегия — многоисточниковый агрегатор с дедупликацией:** HIBP
   (метаданные + email) + XposedOrNot (бесплатная база) + Hudson Rock (stealer)
   + один платный per-query как «глубокая проверка по требованию».

## 2. Приватные протоколы поиска

| Протокол | Как работает | Где применимо | Стоимость реализации |
|---|---|---|---|
| **k-anonymity** | SHA-1 → шлём префикс (5 hex для паролей, 6 для email HIBP) → получаем ~800 суффиксов → матчим локально; `Add-Padding` скрывает даже размер ответа | пароли (готово в HIBP), email (HIBP Pro+) | низкая |
| **OPRF / PSI** | клиент «ослепляет» хэш, сервер применяет PRF не узнавая ничего, клиент «разослепляет»; Google Password Checkup — кривая `secp224r1`, ~4B креденшелов; так же в Apple iCloud Keychain | нужен свой сервер | высокая |
| **Oblivious HTTP (OHTTP)** | релей видит IP но не контент, сервер — контент но не IP; Google даёт Safe Browsing OHTTP Gateway | любой внешний API, включая plaintext-эндпоинты Hudson Rock | средняя |
| **Локальный Bloom / Cuckoo-фильтр** | периодически тянем компактный фильтр всех «плохих» хэшей, проверяем офлайн, в сеть — только при попадании (и то через k-anon) | URL-репутация, breach-проверки | средняя |

**Рекомендация:** Bloom-фильтр + k-anonymity как база; OHTTP — для эндпоинтов,
где plaintext неизбежен; PSI — только если появится свой бэкенд.

## 6. Правовые ограничения

- Хранение сырых дампов «email:пароль» — обработка чужих персональных данных в
  больших объёмах; под GDPR хранение сверх необходимого прямо является
  основанием для санкций.
- **Безопасный дизайн:** не хостим чужие дампы; храним только хэши/префиксы и
  метаданные брешей; свои идентификаторы проверяем через API источников;
  результаты пользователя шифруем локально.
- **HIBP breach/paste API — CC BY 4.0**: обязательна видимая атрибуция со
  ссылкой на haveibeenpwned.com везде, где показываются эти данные.
  Pwned Passwords — атрибуция не требуется.
- **Safe Browsing v5 — только non-commercial.** Коммерческое использование →
  Web Risk. Также GSB требует показывать предупреждение с определённой
  формулировкой и атрибуцией Google.
- Hudson Rock Community API — свободен для community-использования; при
  коммерциализации условия перепроверить.

## 7. AI-эпоха: детект скрытых инструкций (prompt injection)

Ядро продукта (см. [product-vision.md](product-vision.md) §4.1). Готового
коммерческого фида «сигнатур инъекций» на рынке нет — это одновременно риск и
защитный ров: свой корпус и свои сигнатуры становятся активом.

### 7.1 Исследовательская база (данные для правил и корпуса)

| Источник | Что даёт | Как используем |
|---|---|---|
| «Indirect Prompt Injection in the Wild» (arXiv 2604.27202) | 1.2 млрд URL / 24.8 млн хостов → 15.3k подтверждённых внедрений на 11.7k страниц; ~70% в нерендеримом HTML; повторяющиеся шаблоны; цели атак | таксономия носителей, стартовый набор сигнатур, оценка базового уровня FP |
| Замер видимости (обзорные работы 2026) | лишь ~5.1% внедрений видимы пользователю, 58.6% скрыты приёмами рендеринга | обоснование ступени DOM-vs-render diff как основной |
| PhantomLint (arXiv 2508.17884) | принципиальный детект скрытых промптов в структурированных документах | методика для детерминированной ступени |
| IPI-proxy (arXiv 2605.11868) | перехватывающий прокси для ред-тиминга браузерных агентов | основа для нашего тестового стенда и регрессий |
| OWASP GenAI (LLM01:2025) + OWASP Top 10 for Agents 2026 | классификация, рекомендованные митигации (least privilege, human approval, семантический фаервол) | язык описания угроз в UI и структура плейбуков ассистента |
| Unit 42, Brave/Comet PoC, OpenAI Lockdown Mode (13.02.2026) | реальные инциденты и признание неустранимости изнутри | материал для онбординга и позиционирования |

### 7.2 Модели-классификаторы

| Модель | Размер | Пригодность в браузере | Замечания |
|---|---|---|---|
| **Llama-Prompt-Guard-2-22M** | 22M (DeBERTa-xsmall) | **основной кандидат** — ONNX + WebGPU/WASM | −75% латентности к 86M при малой потере качества; устойчивость к атакам на токенизацию (пробелы, фрагментация) |
| Llama-Prompt-Guard-2-86M | 86M | запасной для десктопа | выше качество, выше цена |
| ProtectAI `deberta-v3-base-prompt-injection-v2` | 184M | **отклонён для базовой поставки** | ~1 ГБ + GPU |
| Rebuff | — | **отклонён** | проект архивирован в мае 2025 |

Известное ограничение: guardrail-модели обходятся адверсариальными приёмами
(есть отдельная работа по evasion). Поэтому классификатор — **третья** ступень,
а не единственная; детерминированный diff нельзя обойти, не показав текст
человеку.

### 7.3 Локальный рантайм для ассистента

| Опция | Требования | Статус |
|---|---|---|
| Детерминированные плейбуки | нет | **база, работает всегда** |
| ONNX Runtime Web (WASM/WebGPU) + 22M-классификатор | GPU желателен | основной путь |
| **Chrome Built-in AI (Gemini Nano)**: `LanguageModel`, `Summarizer`, `Writer`, `Rewriter`, `Proofreader` | Chrome 138+, Win10/11 / macOS 13+ / Linux; **≥22 ГБ свободного диска, ≥4 ГБ VRAM**; в расширениях — через origin trial; **не** Android/iOS/ChromeOS | усиление, не зависимость; полностью на устройстве |
| Свой API-ключ пользователя (облако) | явный опт-ин | только по прямому включению |
