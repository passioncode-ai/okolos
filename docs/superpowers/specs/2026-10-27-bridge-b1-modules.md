# Б1 моста: проект и карта модулей (стадия 2)

Основа: [бриф](2026-10-27-bridge-b1-brief.md), [спека](2026-10-06-bridge-b1-design.md). Спека задала модули
K0…K6; здесь они разрезаны до узлов, которые можно закрыть одной проверкой, и добавлено то, чего в спеке
не было: служебная оболочка `fabric-service/0.1`, страница демона и документы.

## Три подхода, выбран первый

| Подход | Плюсы | Минусы | Решение |
|---|---|---|---|
| **A. Демон на Node/TypeScript в этом репозитории**: MCP SDK v2 для двери, Node-набор Fabric для службы, пакеты `core-*` напрямую | движок, снимок и контракты те же, что у расширения, без второй реализации; одна сборка и одни гейты | MCP-сервер Fabric-набора есть только на Python, интероп собирается руками | **выбран** |
| B. Служба на Python с `McpToolServer` из Fabric-набора | интероп и действия готовы | движок Okolos на TypeScript: пришлось бы вызывать его через подпроцесс или переписать; две среды в одном продукте | нет |
| C. Дверь внутри расширения Okolos | нет нового процесса | запрещено ADR-0018: у Okolos нет `nativeMessaging` и `debugger`; состояние задачи умирает со сном service worker | нет |

## Как устроен демон

```
агент ──MCP Streamable HTTP──> 127.0.0.1:47871/mcp
                                │ 1. Host/Origin/Sec-Fetch-Site (набор Fabric)
                                │ 2. ключ привязки → агент; нет ключа → запрос привязки с кодом
                                │ 3. McpServer на этот запрос, инструменты = глаголы Б1
                                ▼
            задачи (область, бюджет, TTL) ── журнал (запись до ответа) ── окно агента (CDP по pipe)
                                                                              │
                                                     снимок: core-snapshot + core-injection
человек ──Fabric Dashboards──> /dashboard: привязки с кодом, активные задачи, отзыв
Fabric ──токен хоста──> /.well-known/fabric-service, /fabric/v1/events, /fabric/v1/login-code
```

- **Две роли ключей.** Токен хоста (файл 0600) читает события и выдаёт коды входа на страницу. На
  `/mcp` он не принимается (`surfaces.mcp.auth: "own"`). Агент ходит только со своим ключом привязки.
- **Привязка.** Привязку ведёт CLI `okolos-agent pair --name "<имя>"`: `POST /pair` создаёт запрос и возвращает код из шести цифр и идентификатор запроса;
  на странице появляется строка «агент X просит доступ, код 123 456». Человек сверяет код и
  подтверждает. CLI забирает ключ через `POST /pair/claim` в течение пяти минут после
  подтверждения; ключ выдаётся один раз и кладётся в файл 0600 клиента. Демон хранит только SHA-256
  ключа в своём хранилище привязок. Вызов `/mcp` без ключа получает 403 `not_paired` и запроса не
  создаёт. Инструмент подтверждения существует (паритет кнопок), но отвечает `human-step-required`.
- **Журнал.** JSONL в каталоге данных, `fsync` до ответа агенту, срок хранения как у журнала
  расширения. Значения полей и тексты страниц в журнал не пишутся: только агент, задача, глагол,
  origin, вердикт, размер ответа, код отказа.
- **Окно агента.** Один Chrome на профиль. Задача открывает своё фоновое окно через
  `Target.createTarget {newWindow: true, background: true}`. `close` закрывает окно задачи; последний
  `close` и остановка демона завершают группу процессов Chrome.
- **Снимок.** Скрипты страницы на паузе; пробник в изолированном мире → `DOM.describeNode` → `Accessibility.getFullAXTree` → `buildSnapshot` (скрытое вырезано, значения полей не
  выдаются) → вердикт `core-injection` по тексту снимка → страница ≤ 32 КБ с курсором. Не удалось
  очистить → агент получает отказ `internal`, не сырое дерево.
- **Перепись.** `ps -axo` и `launchctl list` разбираются в чистой функции; признаки автоматизации,
  владелец, причина «не трогать». Ничего не завершает.

строит дерево той же формы (29 714 узлов) детерминированно, а настоящую большую страницу проверяет e2e
N-017 на локальной фикстуре.
