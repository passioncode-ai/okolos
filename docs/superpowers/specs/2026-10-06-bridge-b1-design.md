# Спека — Okolos Bridge, фаза Б1: мост на чтение

Стадия 3 пайплайна. Написана 2026-10-06 (основа `a4c4863` плюс ветка `bridge/b0`), дополнена прогоном
2026-10-27 ([бриф](2026-10-27-bridge-b1-brief.md), [карта модулей](2026-10-27-bridge-b1-modules.md)): разделы 8–11 добавлены, разделы 1–3 и 5 уточнены ревью.

**Источники:**
- решения: ADR-0018, ADR-0019, стратегия §8.6–8.7;
- сценарии: SCN-044, SCN-045, SCN-048 (`docs/ux/scenarios.md`);
- замеры: [evidence/2026-10-06-b0-agent-window.md](../evidence/2026-10-06-b0-agent-window.md);
- архитектура: отчёт `okolos/2026-10-05-agent-browser-bridge` (база знаний продукта, вне этого
  репозитория).

**Что Б1 даёт человеку:** его агенты читают страницы через одну локальную дверь. Профиль агента в Б1
начинается без входов на сайты, и шага входа в Б1 нет (это SCN-047 в Б2); вход, который человек сделал
вручную в окне агента, в профиле остаётся (SCN-045).
Что они читают, очищено от скрытых инструкций. Секретов они не видят, фокус не забирают. Вместо
браузерного MCP-сервера в каждой сессии работает один демон. **Действий в Б1 нет** — это Б2.

ревью магазина. Первая ценность приходит без недель ревью.

**Walking skeleton.** Агент вызывает `session.open` → демон запускает окно агента → `open`
локальной фикстуры → `snapshot` со следом одной находки из корпуса → `close`. Путь проходит
через e2e на настоящем Chrome до появления второго глагола.

## 2. Контракты (K0)

covers: REQ-53, REQ-59

### 2.1 Задача

```ts
interface TaskScope {
  goal: string                 // цель человека, словами агента; читает сторож дрейфа (Б3)
  origins: { read: string[]; write: string[] }   // точные origin; write ⊆ read
  verbs: BridgeVerb[]          // подмножество закрытого набора
  ttlSeconds: number           // ≤ 3600
  stepBudget: number           // ≤ 500 вызовов
  profile: 'agent' | 'disposable'   // agent — постоянный профиль, входы в нём сохраняются (начинается без входов; шага входа в Б1 нет, это SCN-047 в Б2, но вход, сделанный человеком вручную в окне агента, остаётся, SCN-045); disposable — временный
}
```

### 2.2 Глаголы Б1 (только чтение)

| Глагол | Вход | Выход |
|---|---|---|
| `session.open` | `TaskScope` (поле `profile` обязательно) | `{ sessionId, windowId }`; `sessionId` из 128 случайных бит, задача принадлежит открывшему агенту |
| `open` | `{ url }` из `origins.read`, или `{ ref }` ссылки на текущей странице, чья цель тоже в `origins.read` | `{ url }`: фактический URL после навигации, без фрагмента |
| `snapshot` | `{ ref?: string, cursor?: string, maxBytes?: number }` | `{ text, refs, verdict, cursor?: string, partial: boolean }`; `verdict` целого снимка на каждой странице |
| `read` | `{ ref?: string, maxBytes?: number }` | `{ text, boundary: { nonce, origin } }`; текст только из очищенных строк снимка |
| `get` | `{ what: 'url' \| 'title' \| 'text' \| 'count', ref?: string }` | значение; `text` и `title` из очищенного снимка, `url` без фрагмента |
| `waitFor` | `{ ms } \| { text } \| { url }` | `{ text }` ищется только в очищенном снимке |
| `close` | нет | окно и процессы задачи закрыты; разрешён всегда, даже если не назван в `verbs` |
| `hygiene.census` | нет | перепись (K5) без командных строк чужих процессов |

**Формы входа и выхода, принятые в N-023** (тип `VerbIO` в `packages/contracts/src/bridge.ts`, их
единственный дом): каждый глагол внутри задачи принимает `sessionId` задачи (`TaskCall`);
`WaitForResult` равен `{met: boolean}`; `GetResult` помечен по `what` (`count` даёт число, остальные
строку); `CloseResult` равен `{closed: true}`; `CensusResult` равен `readonly CensusEntry[]`. Глагол
пишется с точкой (`session.open`) в контрактах и журнале; имя инструмента MCP даёт `toolName(verb)`
(`session_open`), обратно `canonicalVerb`.

`screenshot` перенесён в Б2 (ревью 2026-10-27, F3): пиксели обходят движок и показывают введённые
номера карт и коды. Вернётся вместе с маскированием полей.

Набор совпадает с драйвером исполнителя сценариев, который согласовал его 2026-10-05: закрытые
глаголы, навигация по allowlist или `ref`, фактический URL после навигации, своё окно на задачу.

### 2.3 Конверт и отказы

```ts
type BridgeResult<T> = { success: true; data: T } | { success: false; error: { code: BridgeRefusal; message: string; retryable: boolean } }
type BridgeRefusal =
  | 'not_paired' | 'invalid_scope' | 'no_such_task' | 'origin_not_in_task' | 'verb_not_in_task'
  | 'budget_exhausted' | 'task_expired' | 'tab_gone' | 'busy' | 'in_use_by_person'
  | 'browser_offline' | 'blocked_by_shield' | 'cleaning_incomplete' | 'stale_cursor' | 'internal'
```

Отказ политики — `retryable: false`. Повтор после отказа списывается с бюджета задачи.

## 3. Правила, которые держит код Б1

| Привязка человеком, со сверкой кода, по правилам §11 F5. Ключ агента 256 бит, демон хранит только его SHA-256 в своём хранилище привязок (одно авторитетное хранилище, 0600), сравнение `timingSafeEqual`. Отзыв закрывает задачи агента | K3 | юнит-тесты правил привязки; e2e SCN-044 |

Решения, которых спека 2026-10-06 не принимала (подробно в брифе и карте модулей):

- **Где страница привязки.** У демона, служба `fabric-service/0.1` `okolos-agent.default` на
  `127.0.0.1:47871`, страница `/dashboard` открывается в Fabric Dashboards.
- **Две роли ключей.** `surfaces.mcp.auth: "own"`: `/mcp` не принимает токен хоста; агент ходит
  только со своим ключом.
- **Привязка по шагам.** CLI или stdio-шим вызывает `POST /pair` и получает код и
  `pairingRequestId`; человек подтверждает на странице; CLI забирает ключ через `POST /pair/claim`
  один раз, в течение пяти минут после подтверждения. Демон хранит SHA-256 ключа в хранилище
  привязок. Вызов `/mcp` без ключа: 403 `not_paired`, запроса не создаёт. Инструмент подтверждения
  отвечает `human-step-required` (шлюз `human`, шаг `consent`). Подробно: §11 F5, F6.
- **Каталоги** по `fabric-service/0.1`: данные `~/Library/Application Support/okolos-agent/`, логи
  `~/Library/Logs/okolos-agent/`, код из релиза `~/.local/share/okolos-agent/releases/`.
- **REQ-56** проверяется деревом формы Википедии (29 714 узлов), построенным детерминированно: замер
  Б0 сохранил только размеры.
