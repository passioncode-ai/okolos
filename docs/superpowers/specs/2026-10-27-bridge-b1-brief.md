# Бриф прогона: Okolos Bridge, фаза Б1 (B-142)

Артефакт стадии 0 task-pipeline. Спека уже есть: [2026-10-06-bridge-b1-design.md](2026-10-06-bridge-b1-design.md).
Этот бриф её не повторяет, а фиксирует то, чего в ней нет: что уже построено, решения, которые
спека оставила открытыми, полный список требований и ответы на вопросы стадий 1–10.

- **Дата:** 2026-10-27
- **Задача одной строкой:** построить мост на чтение: демон Okolos Agent с MCP-дверью и привязкой
  агентов, окно агента, снимок частями, перепись процессов (REQ-53…REQ-63), трек RM-18.
- **Кто поставил:** оператор, 2026-10-26, «давай вперед» на план, четвёртый пункт которого был
  «Взять Б1 моста (B-142)»; координатор fabric-workspace 2026-10-27 передал «пушни всех агентов
  продолжить свои задачи».

  Трек UX стадии 3 взведён.
- **surface_class:** `product`. Это обычный экран продукта, не лендинг и не онбординг; но это экран

  (строка B-151). Нижняя планка: e2e SCN-044 и SCN-045, проход доступности, `e2e/panel-shape.spec.ts`.

## Финишная черта

- **Цель:** агент, привязанный человеком, через локальную дверь Okolos Agent открывает задачу,
  читает страницу в своём фоновом окне очищенной и частями, а всё, что он получил, есть в журнале.
- **Проверки выхода:** `pnpm gates` → 0; e2e моста на Chrome stable (walking skeleton и SCN-044,
  SCN-045) → 0; установленный демон: `check_service.py` → 0 FAIL, вызов `session.open` → `snapshot`
  → `close` из Claude Code по MCP проходит на установленной службе.
- **Объём:** `packages/contracts`, `packages/cdp-pipe`, `packages/core-snapshot`, `apps/agent`,
  `tools/install-agent.mjs`, `docs/`, `AGENTS.md`; REQ-53…REQ-70.
- **Бюджет:** `maxRounds` 3, `maxReleases` 2 (значения по умолчанию).
- **База:** `5d664c5` (main), ветка `bridge/b1-run2` от `67ffa59` (перебазированный `39a2bdd` из `bridge/b1`).

## Решения

| # | Решение | Выбрано | Почему |
|---|---|---|---|
| 1 | Начать заново или продолжить | Продолжить `bridge/b1`, перебазированную на `main` | Фундамент K0 и K2 построен и зелёный; «resume, never restart blindly» |
| 2 | Где живёт панель привязки и вид активности | Страница самого демона, его дашборд `fabric-service/0.1`, открывается в Fabric Dashboards | Расширения моста в Б1 нет (спека §4); Okolos не может говорить с демоном: у него нет и не будет `nativeMessaging` (ADR-0018); страницы агентов открываются только в Fabric Dashboards (правило оператора 2026-10-24); согласие через хаб Fabric (ADR-0115) появится, когда хаб будет готов |
| 3 | Среда демона | Node.js, TypeScript, собирается так же, как `tools/`; launchd-агент `app.okolos.agent` в `gui/<uid>`; слушает только `127.0.0.1` | Один язык и одна сборка с остальным репозиторием; launchd как у агента фида |
| 4 | MCP | Официальный SDK v2: `@modelcontextprotocol/server` 2.4.0 и `@modelcontextprotocol/node` 2.1.2 (Apache-2.0; зависимости `zod`, `hono`, `@hono/node-server` под MIT); транспорт на каждый запрос, без сессий; проверки `Host`, `Origin` и ключа стоят до обработчика | Стадия 1, ниже. В Node-наборе Fabric MCP-сервера нет, он есть только в Python-наборе |
| 5 | Что хранится в связке ключей | Проверочный отпечаток ключа (SHA-256), не сам ключ; ключ отдаётся агенту один раз при привязке | Демону для сверки нужен только отпечаток; так значение не попадает ни в аргументы `security`, ни в журнал |
| 6 | Профиль окна агента | `agent`: постоянный каталог в данных службы, `~/Library/Application Support/okolos-agent/profiles/agent`; `disposable`: `mkdtemp`, удаляется при `close` | Спека §2.1; логины человека не импортируются (App-Bound Encryption) |
| 7 | Какой Chrome | Установленный Google Chrome stable; если его нет, `browser_offline` с причиной. Тесты: тот же бинарник на временном профиле, все процессы закрываются | Инфобар меряется только на stable (у Chrome for Testing свой постоянный, замер Б0); правило оператора: Chrome только по необходимости, никогда профиль оператора. CDP по pipe есть только в Chromium |
| 8 | Журнал | Только дописывание, JSONL с `fsync` до ответа; срок хранения как у журнала расширения (число берётся командой из `RETENTION_DAYS`) | ADR-0019: ответ без записи нарушает анти-цель |
| 9 | Как ветка попадает в `main` | PR, merge-коммит (история так делает), после зелёных `pnpm gates` и e2e моста | `AGENTS.md`; правило оператора о PR |
| 10 | Тексты для людей | Через бренд-пак; каждая новая строка проходит `copylot_check` в каждой локали, где она есть | Правила проекта и оператора (2026-10-25) |

## Критерии готовности

- Агент, привязанный через панель, открывает задачу и получает очищенный снимок частями; отказы
  приходят кодами контракта; каждый ответ есть в журнале.
- Демон установлен под launchd, виден в Fabric Dashboards, переживает `kill -9`, окна агента не
  оставляют сирот.
- `pnpm gates` и e2e зелёные, ветка влита в `main`, документы и база знаний говорят правду.

## Допущения и риски

- MCP SDK может не дать проверить `Host`/`Origin` до разбора запроса. Проверка на стадии 1,
  запасной путь в решении 4.
- Chrome на машине может уйти на 155 и сменить поведение pipe-CDP на не-дефолтном профиле. Тест
  окна агента это покажет; запасной путь Б2 (спека §5).
- e2e окна агента запускает настоящий Chrome на машине, где работает человек. Окна только фоновые,
  профиль временный, все процессы закрываются, фокус проверяется тестом.
