# Б0, окно агента: замеры 2026-10-06

Что проверялось: работает ли вторая дверь моста — «окно агента», то есть установленный Chrome
человека на отдельном профиле под CDP через `--remote-debugging-pipe` — так, как предполагает
стратегия (§8.6). Инструмент: [`tools/agent-window-spike.mjs`](../../../tools/agent-window-spike.mjs).
Его чистые части — разбор кадров pipe, сжатие AX-дерева, счёт сообщений по 1 МБ — держит
`tools/agent-window-spike.test.ts`.

Сырые результаты лежат рядом: [run2](2026-10-06-b0-agent-window-run2.json) и
[run3](2026-10-06-b0-agent-window-run3.json). Run1 перезаписан run2. Из него сохранено одно
наблюдение о фокусе — ниже, со ссылкой на то, что файла нет.

Среда:
- Google Chrome **154.0.8037.98** (stable);
- Google Chrome for Testing 154.0.8037.57;
- macOS 26.6.2, рабочая станция оператора, во время замера на ней работал человек.

Повторить замер:

```bash
node tools/agent-window-spike.mjs --out /tmp/b0.json
```

## Что из этого следует для спеки Б1

1. **Окно агента — рабочая дверь без инфобара**, на установленном Chrome, без своего форка и без
   расширенческого `debugger`. Это подтверждает решение из стратегии §8.6.
2. **Задача — это своё окно с активной вкладкой, а не фоновая вкладка.** Ввод в скрытую вкладку не
   доставляется. Это относится и к двери-расширению: группа вкладок в окне человека для действий
   не годится. Задаче нужно отдельное окно (`windows.create {focused: false}`), а группа остаётся
   разве что подписью.
3. **Запуск — `--no-startup-window`, окна — через CDP с `background: true`.** Обычный запуск в
   двух случаях из трёх уводил фокус у человека.
4. **Сжатие снимка обязательно, и одного сжатия мало.** Сжатая Википедия — около 66 тыс. токенов.
   Нужна выдача снимка по частям: видимая область, поддерево по `ref`, страницы с курсором.
   Сырое дерево через Native Messaging не передаётся никогда. В сторону расширение → хост предел
   64 МиБ, но сырые 11 МБ на каждый шаг — расход без пользы.
5. **Инфобар двери-расширения считаем показанным.** Подавить его в сторовой сборке нечем, кроме
   политики предприятия (force-install). В интерфейсе он работает как честный сигнал «агент
   работает».

## Не покрыто

- **Chrome 155 stable:** на машине в момент замера был 154. Ограничение Chrome 155 для
  `chrome.debugger` под политиками касается расширений, а окно агента его не использует. Повторить
  замер после обновления — строка в бэклоге.
- **Политики предприятия** (`CommandLineFlagSecurityWarningsEnabled`, заблокированные хосты, DLP):
  на машине оператора не включались намеренно.
- **Высота рамки — косвенный признак инфобара.** Читать его можно только потому, что рядом стоит
  положительный контроль. Скриншот окна не снимался, чтобы не снимать экран человека.
- **Фокус измерен на живой станции:** в части замеров впереди были приложения человека (Orca,
  Telegram, Safari). Выборка маленькая — 3 запуска.
- **Edge, Brave и другие Chromium не мерились;** Firefox и Safari — вне этого замера по
  определению (`architecture.md` §7 отчёта).
