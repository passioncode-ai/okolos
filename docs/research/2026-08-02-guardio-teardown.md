## 1. Что это и как позиционируется

**Одной строкой:** браузерное расширение (Chrome/Edge) + веб-дашборд + мобильное
приложение, продаётся как «защита от скама/фишинга/утечек» для нетехнической
аудитории по подписке.

**Ключевые заявления с лендинга:**

- «Protect everything you do and own online».
- Блокирует ~50% фишинга, приходящего в почту/SMS.
- «Predicts, detects, blocks» — AI-анализ страницы **до** её открытия.
- Детект «персонализированных AI-скамов» на публичных данных.
- Соцдоказательства: 1.5M+ пользователей, упоминания Forbes/PCMag/TechRadar,
  собственный ресёрч-отдел Guardio Labs.

**Целевая аудитория:** нетехнические частные лица и семьи (плюс отдельный
B2B-тариф). Продукт продаёт **спокойствие**, а не технологию: интерфейс —
счётчики угроз, зелёные галки, «resolve» кнопки.

**Бизнес-модель:** free-tier как приманка (сканы + алерты, но без блокировок),
всё ценное за пейволом. Тарифы:

| План | Помесячно | Годовой | На чел. |
|---|---|---|---|
| Free | $0 | — | — |
| Individual | $14.99/мес | $119.88/год | $9.99/мес |
| Duo (2) | $22.99/мес | $183.90/год | $7.67/мес |
| Family (5) | $34.99/мес | $279.90/год | $4.67/мес |
| VIP | доплата | — | приоритетный саппорт + сессии с «экспертом» |

Free-trial убран, окно возврата ~3 дня → основной поток жалоб (см. §5).

## 2. Разбор фич по экранам админки

### 2.1 Overview (главная)
- «Set up protection 2/5» — прогресс-бар онбординга, вечный нагоняй.
- **Recommendations** — заблюрены, кнопка «Unlock Recommendations» (пейвол,
  замаскированный под «у тебя есть проблемы»).
- **Your Security Status** — 6 счётчиков: Data Leaks Found (26), Malicious Email
  Alerts (—, «Set Up»), Suspicious Site Alerts (203), Unwanted Notifications
  Blocked (0), Malicious Extensions Detected (0), Search Hijackers Alerts (0).
- **Device Information**: страна, платформа (`Mac OS X 10.15.7` — UA-строка),
  браузер (`Chrome 150`), кол-во установленных расширений (17), IP-адрес.
- Верхняя плашка: «Last scan 22 weeks ago / Scan Now» + жёлтый баннер «We've
  added new features that require additional permissions → Grant Permissions».

**Вывод:** дашборд построен на **счётчиках тревоги**. Числа большие (203, 26), но
неактивные — это витрина для апсейла, а не операционный инструмент.

### 2.2 Browsing Protection
- **Browsing Activity** — журнал событий с сервера: `TIME & DATE | EVENT | DETAILS
  | RECOMMENDATIONS`, 203 события, 29 страниц пагинации, вкладки Recent/Allowed.
  Пример строки: `28/07/2026, 11:56 — Opened a public document — docs.google.com`.
- Тумблеры: **Harmful Site Blocks** (вкл), **Dangerous Download Blocks**
  (PREMIUM, выкл), **Suspicious Site Alerts** (вкл), **Webcam & Microphone
  Alerts** (вкл).

**Критично:** журнал «что ты открывал» живёт **на их сервере** и рендерится в
веб-дашборде. Значит URL/домены (как минимум) уходят наружу и хранятся
персонализированно месяцами. Это и есть главная точка, которую мы убираем.

### 2.3 Extensions
- Заголовок «Malicious Extension Detection» + апсейл.
- **Automatic Removal** (PREMIUM, выкл), **Pre-Install Alerts** (вкл).
- Список Installed (17) карточками: иконка, имя, кол-во пользователей
  (600 000 / 200 000 / 3 000 000), рейтинг стора (3.0 / 3.5 / 3.9), тумблер
  вкл/выкл. Вкладка Neutralized — PREMIUM.

**Как работает:** `chrome.management` даёт список расширений и `setEnabled()`.
Метрики (users/rating) подтягиваются из данных Chrome Web Store. Вердикт —
их собственный чёрный список + эвристики по разрешениям.

### 2.4 Notifications
Блокировка «непрошеных» push-уведомлений сайтов (счётчик на Overview). Технически
— управление `contentSettings` для notifications + чёрный список доменов.

### 2.5 Identity (самая ценная фича)
- **Monitoring List**: источники — email и телефон
  оператора (значения удалены из публичной копии), кнопка «Add Source» (можно добавлять ещё).
- Таблица утечек: `BREACH NAME | DATE PUBLISHED | COMPROMISED DATA` c тегами
  (`EMAIL`, `PASSWORD`, `FULL NAME`, `IP ADDRESS`). Пагинация — 6 страниц.
- Названия источников: реальные бренды (Trello, Twitter/X, Jefit, Euro-PvP.Ru) и
  обобщённые (`Available on the dark web`, `Source is hidden`,
  `Cryptocurrency Platform Data`).
- Отдельный блок **Archived Leaks** (разобранные пользователем).

**Как работает:** это агрегатор breach-датасетов (свой + купленные фиды). Паттерн
`Source is hidden` / `Available on the dark web` — типичная маскировка комбо-листов
и stealer-логов, у которых нет чистой атрибуции к конкретному сервису.

### 2.6 Hijackers (Search Hijacking Correction)
- Выбор предпочитаемого поисковика — **PREMIUM** (даже Google в списке залочен).
- Recent activity: `EVENT | SOURCE | DATE & TIME`.
- Три объяснялки «как это происходит / что происходит / насколько опасно».

**Как работает:** сравнение фактического search provider и цепочек редиректов с
ожидаемым; в MV3 корректный путь — `chrome_settings_overrides` + детект
редиректов через `webNavigation`/`declarativeNetRequest`.

### 2.7 Email Security
- **Real-Time Protection** — тумблер залочен (PREMIUM).
- Таблица алертов: `DATE | SENDER | SUBJECT | REASON`.
- Явно и только про **Gmail-инбокс**.

**Как работает:** OAuth-доступ к Gmail API (либо контент-скрипт поверх
mail.google.com) → анализ отправителя/ссылок/вложений. Это самое «жирное» по
приватности разрешение во всём продукте.

### 2.8 Mobile App
iOS/Android: фильтрация скам-SMS, алерты. На iOS это SMS-фильтр-экстеншн, на
Android — SMS/Call screening.

## 3. Техническая модель Guardio (как это устроено)

**Разрешения расширения:** «read and change all your data on all websites»
(host permissions `<all_urls>`), notifications, management (управление
расширениями), плюс отдельный OAuth Google для почты.

**Что собирают** (по их же privacy policy и обзорам): анонимизированное
поведение при браузинге, включая **посещённые сайты и URL**, страна, IP, время
установки, email, имя/фамилия, для платящих — последние 4 цифры карты и тип
карты. При этом заявляют «не продаём третьим лицам».

**Как детектится сайт:** заявлено «page understanding + threat pattern
recognition», а не только URL-репутация: структура домена, поведение страницы,
признаки имперсонации бренда. То есть гибрид: серверная репутация URL +
клиентские/серверные эвристики по содержимому.

**Архитектурный вывод:** это классический **cloud-first** дизайн — расширение
тонкое, вся логика и вся история на сервере. Отсюда и их фичи (дашборд с
историей на любом устройстве), и их главный недостаток (вы отдаёте карту своего
браузинга навсегда).

## 4. Что у них хорошо (стоит скопировать)

1. **Онбординг-прогресс** «2/5 completed» — простая механика доведения до
   ценности.
2. **Единый дашборд** вместо разрозненных тулзов: браузинг + утечки + расширения
   + почта в одном месте.
3. **Понятные теги утечек** (`PASSWORD`, `EMAIL`, `IP ADDRESS`) — человек сразу
   понимает степень боли.
4. **Archived Leaks** — состояние «я это разрулил», иначе список утечек вечно
   красный и обесценивается.
5. **Pre-Install Alerts** для расширений — предупреждать ДО установки, а не после.
6. **Мультиисточники в мониторинге** (email + телефон + «Add Source»).
7. Собственный ресёрч-бренд (Guardio Labs) как маркетинговый двигатель.

## 5. Что у них плохо (наши возможности)

| Проблема | Наша возможность |
|---|---|
| **Вся история браузинга на их сервере**, привязанная к аккаунту | local-first: журнал только на устройстве, сервер видит максимум хэш-префиксы |
| Агрессивный пейвол: заблюренные «рекомендации», залоченный выбор Google как поисковика | без dark-pattern'ов; либо self-hosted/бесплатно для себя |
| Жалобы: сложная отмена, двойные списания, отказ в возврате, 3 дня на refund | нет биллинга вообще (личный продукт) или честный |
| «Last scan 22 weeks ago» — сканы не автоматические | планировщик + фоновая инкрементальная проверка |
| Счётчики ради тревоги (203 алерта, ничего не сделано) | приоритизация: «что реально сделать сейчас», 3 действия вместо 203 строк |
| Утечки без действия — просто список | actionable: сгенерировать смену пароля, проверить повтор пароля, включить 2FA, отследить бренд |
| Vendor lock: данные и правила у них | открытые фиды, экспорт, свой индекс |
| Только Chrome/Edge + Gmail | Firefox/Safari, IMAP/Proton, локальный разбор |

## 6. ИСТОЧНИКИ ДАННЫХ (главный раздел)

### 6.1 Утечки/breach-данные

#### A. Публичные и бесплатные

| Источник | Что даёт | Формат | Цена | Приватность |
|---|---|---|---|---|
| **HIBP Pwned Passwords** | ~1B+ хэшей паролей (SHA-1 + NTLM) с частотой | k-anon API `range/{5 hex}` **или полный корпус на скачивание** | **бесплатно**, без ключа, без лимита, без атрибуции | ★★★★★ (k-anonymity + `Add-Padding: true`) |
| **HIBP breach metadata** | список 1022+ брешей, описания, dataClasses | `/breaches`, `/breach/{name}` | бесплатно | n/a (публичные факты) |
| **XposedOrNot** | breach-поиск по email, экспозиция паролей, domain-риск | JSON API, **open-source** (есть SDK Go/Rust/.NET) | бесплатный тариф + платный xonAPI+ | хорошая (есть anon-режимы) |
| **Hudson Rock Cavalier Community API** | **infostealer-логи** по email / домену / username | `cavalier.hudsonrock.com/api/json/v2/osint-tools/search-by-*` | **бесплатно, без ключа**, 50 req/10s | средняя (уходит plaintext email) |
| **Hudson Rock free monitoring** | мониторинг 3 email + 3 домена + 3 username с алертами | веб | бесплатно | средняя |

#### B. Платные (по цене за запрос — то, что имеет смысл)

| Источник | Покрытие | Цена (ориентир 2026) |
|---|---|---|
| **HIBP API** (Core/Pro/High-RPM) | email→breach, k-anon email search, **stealer logs**, domain search | от ~$4.4/мес; enterprise-поиск ~$0.05 |
| **DeHashed** | email, username, IP, телефон, **пароли/хэши** | ~$0.02–0.25 за запрос, pay-as-you-go |
| **LeakCheck** | 7B+ записей: email/username/phone/keyword/domain | $9.99/мес (200 email/день), lifetime $24.99 |
| **Snusbase** | комбо-дампы, поиск по многим полям | $5–16/мес, API до 2048 req/день |
| **Leak-Lookup / BreachDirectory** | агрегаторы дампов | дешёвые per-query тарифы |
| **Enzoic** | проверка креденшелов в момент логина/смены пароля | B2B-подписка |
| **Intelligence X** | архивы, darkweb, документы | дорого: от €2 500/год, API-тариф в разы дороже |
| **Breachsense / LeakRadar** | свежие stealer-логи, B2B-мониторинг | подписка |

#### C. Ключевая находка по источникам

1. **Infostealer-логи ≠ breach-дампы.** Guardio показывает их как
   «Available on the dark web» / «Source is hidden». Это **самый актуальный и
   самый опасный** класс данных (свежие сессии, куки, автозаполнение), и по нему
   есть **бесплатный** источник — Hudson Rock Cavalier. HIBP даёт stealer logs
   только на Pro+.
2. **Пароли можно проверять полностью офлайн.** Корпус Pwned Passwords
   скачивается целиком (PwnedPasswordsDownloader) → локальный индекс → **ноль
   сетевых запросов**, ноль утечки, лицензия не требует даже атрибуции. Это
   лучше, чем у Guardio.
3. **Атрибуция обязательна** для HIBP breach/paste API — CC BY 4.0, надо явно
   указывать источник.
4. **Реалистичная стратегия — многоисточниковый агрегатор** с дедупликацией:
   HIBP (метаданные+email) + XposedOrNot (бесплатная база) + Hudson Rock
   (stealer) + один платный per-query (DeHashed/LeakCheck) как «глубокая
   проверка по требованию».

#### D. Приватные протоколы поиска (как не сдать свой email/пароль)

- **k-anonymity (HIBP):** пароль — SHA-1, шлём 5 hex-символов префикса, получаем
  ~800 суффиксов, матчим локально. Для email HIBP использует 6-символьный
  префикс SHA-1. Сервер не знает, что именно искали. Плюс `Add-Padding` — чтобы
  даже размер ответа не выдавал префикс.
- **PSI / OPRF (Google Password Checkup, Apple iCloud Keychain):** клиент
  «ослепляет» хэш случайным множителем, сервер применяет PRF, не узнавая ничего,
  клиент «разослепляет» и сверяет с предзагруженным множеством. Google
  использует эллиптическую кривую `secp224r1` поверх ~4B креденшелов. Это
  сильнее k-anon, но требует своего сервера.
- **Oblivious HTTP (OHTTP):** запрос идёт через независимый релей — сервер видит
  контент, но не IP; релей видит IP, но не контент. Google предлагает это в Safe
  Browsing v5 как отдельный гейтвей.
- **Локальный Bloom/Cuckoo-фильтр:** периодически тянем компактный фильтр всех
  «плохих» хэшей, проверяем офлайн, в сеть ходим **только при попадании** (и то
  через k-anon). Наилучший приватностный компромисс для нашего случая.

#### E. Правовой аспект (важно!)

Хранить у себя сырые дампы «email:пароль» — это обработка чужих персональных
данных в больших объёмах; под GDPR это создаёт реальный риск (хранение сверх
необходимого прямо названо основанием для санкций). Практический безопасный
дизайн для личного продукта:

- **не хранить** сырые дампы третьих лиц;
- хранить только **хэши/префиксы** и метаданные брешей;
- проверять свои идентификаторы **через API источников**, а не путём загрузки
  чужих баз;
- локально — только **свои** результаты, шифрованные на устройстве.

| **PhishTank** | база фишинга + API | бесплатно; регистрация новых закрыта | полная |

| **Phishing Army / phishing-filter / threat-hostlist** | агрегированные блок-листы (PhishTank+OpenPhish+CERT.pl+urlscan+Phishunt), обновление 6ч | бесплатно | полная |

**Проактивные (upstream) источники — то, чего у Guardio в явном виде нет:**

- **CertStream (Calidog)** — real-time поток Certificate Transparency: видно
  каждый новый TLS-сертификат в момент выпуска. Фишинг почти всегда получает
  сертификат за часы до атаки.
- **NRD-фиды** (whoisds — бесплатный дневной список новых доменов; whoisfreaks —
  платный с WHOIS/DNS). Возраст домена < 30 дней — сильнейший единичный
  признак.
- **dnstwist / typosquat-генерация** вокруг брендов, которыми пользуется
  конкретный пользователь (его банк, его биржа) — персональный watchlist вместо
  глобального.
- **Tranco** — список популярных доменов для аллоулиста и для детекта
  «похож на топ-бренд, но не он».

### 6.3 Расширения браузера

- `chrome.management` — локальный инвентарь + возможность выключать.
- **CRXPlorer** — бесплатный сканер CRX (разрешения, подозрительный код).
- **Secure Annex / ExtensionTotal / Spin.AI / LayerX** — коммерческие
  risk-scoring фиды (CRXcavator от Duo мёртв с 2023).
- **chrome-stats.com** — метаданные стора (users, rating, история версий,
  смена владельца).
- **Свой статический анализ**: скачать CRX → распаковать → проверить
  `permissions`, `host_permissions`, наличие `eval`, обфускацию, удалённые
  эндпоинты, дельту разрешений между версиями (**смена владельца + резкий рост
  разрешений** — главный сигнал заражения; свежий кейс марта 2026).

### 6.4 Email/SMS

- Gmail API (OAuth, read-only) — как у Guardio, но можно **разбирать локально**.
- IMAP для остальных провайдеров (Proton Bridge, Fastmail, свой).
- Проверки: SPF/DKIM/DMARC, mismatch отображаемого имени и адреса, свежесть
  домена отправителя, URL из письма через те же URL-фиды, вложения по хэшу
  (MalwareBazaar).

## 7. Технические ограничения (Chrome MV3, 2026)

- MV2 полностью отключён; только service worker (эфемерный, без долгих таймеров
  → нужен `chrome.alarms`).
- Блокировка — `declarativeNetRequest`: **до ~330 000 статических правил и
  ~30 000 динамических**. Глобальные фишинг-листы (~250k+) в динамические не
  влезают → нужна гибридная схема: статический пакет в билде + динамика только
  для «горячих» доменов + локальная проверка хэшей в SW.
- `webRequestBlocking` недоступен → предупреждение делается через
  `webNavigation.onBeforeNavigate` + редирект на свою страницу блокировки.
- Плюс приватности: DNR-правила выполняются в браузере, расширение **не видит**
  сами запросы.
- Локальный ML реален: WebLLM/WebGPU или TF-Lite/ONNX в SW (есть рабочие
  примеры client-side детекторов фишинга, включая академический PhishLang).

## 8. Идеи улучшений (что сделать лучше Guardio)

**Приватность (наш главный дифференциатор):**
1. Local-first: история браузинга **никогда** не покидает устройство; сервера
   может не быть вообще.
2. Все проверки — по k-anon префиксам / локальным Bloom-фильтрам; сеть только
   при попадании.
3. Опциональный OHTTP-релей для внешних API (даже IP не отдаём).
4. Локальный корпус Pwned Passwords — офлайн-проверка паролей.
5. E2E-шифрованный опциональный синк между своими устройствами (ключ у
   пользователя, сервер — «слепое» хранилище).

**Детект (сильнее, чем у них):**
6. Проактивный слой: CertStream + NRD → персональный watchlist по брендам, с
   которыми ты реально работаешь (банк/биржа/почта), а не «весь интернет».
7. Локальная визуальная проверка имперсонации: сравнение favicon/лого/структуры
   формы логина с эталоном настоящего бренда.
8. Скоринг вместо бинарного вердикта: возраст домена + CT + репутация + похожесть
   на бренд + наличие формы пароля → объяснимый score с причинами.
9. Мониторинг расширений: диффы разрешений между версиями и смены владельца
   (то, что реально ломает людей в 2026).
10. Crypto/Web3-слой (у тебя в списке TronLink и Tonkeeper): детект
    drainer-сайтов, подозрительных `approve`-транзакций, фейковых кошельков.

**Actionability (у них слабое место):**
11. Не «203 алерта», а очередь из 3 действий с оценкой эффекта.
12. Для каждой утечки — прямая ссылка на смену пароля (`/.well-known/
    change-password`), чек «этот пароль переиспользован ещё где-то», статус 2FA.
13. Diff-режим: «что изменилось с прошлой недели», а не вечный красный список.
14. Автосканы по расписанию, а не «last scan 22 weeks ago».

**Прозрачность:**
15. Открытые правила/фиды + локальный лог того, какие сетевые запросы делает сам
    продукт (self-audit — «мы показываем вам, что мы отправили»).
16. Экспорт всех своих данных в JSON в один клик.

## 9. Развилки, которые надо решить на брейншторме

1. **Форма продукта:** только расширение (local-first, без сервера) / расширение
   + свой self-hosted бэкенд / + мобильное приложение.
2. **Один пользователь (ты) или продукт для других** — от этого зависят
   биллинг, юридическая обвязка, мультиарендность.
3. **Бюджет на платные фиды** (HIBP Pro нужен для stealer-логов; DeHashed —
   per-query «глубокая проверка»).
4. **Коммерческий статус:** Safe Browsing v5 бесплатен **только для
   non-commercial**; коммерческий путь — Web Risk ($0.50/1000 сверх 100k).
5. **Браузеры:** только Chrome/Edge или + Firefox (MV2/MV3-совместимость) и
   Safari.
6. **Почта:** Gmail OAuth (удобно, но самое чувствительное разрешение) или
   локальный IMAP-разбор.
7. **Где хранить индекс:** полностью локально (SQLite/IndexedDB) или
   self-hosted (Postgres + Meilisearch/ClickHouse).
