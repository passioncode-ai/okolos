## 1. Одно предложение

**Okolos — браузерная защита для эпохи AI-агентов: находит на странице скрытые
инструкции, подсунутые твоему AI, проверяет каждую ссылку и каждую загрузку,
следит за расширениями и утёкшими паролями — и дружелюбный ассистент проводит
тебя через починку. Всё считается локально, история браузинга не покидает
устройство.**

## 2. Почему именно сейчас

Классические антифишинги защищают **человека, который смотрит на экран**. Но всё
чаще страницу читает не человек, а агент: сайдбар браузера, AI-браузер, кодовый
агент, расширение-суммаризатор. И у этой поверхности защиты **нет**.

Факты, на которых стоит продукт:

- **Это уже не теория.** Эмпирическое исследование 2026 года: просканировано
  1.2 млрд URL на 24.8 млн хостов → **15 300 подтверждённых внедрений на 11 700
  страницах**; повторяющиеся шаблоны — то есть массовое, организованное
  применение, а не единичные PoC.
- **Прячут почти всегда.** ~70% инструкций живут в нерендеримых частях HTML
  (комментарии, meta, заголовки, атрибуты); по другому замеру лишь **~5%
  внедрений видимы пользователю**, ~58.6% скрыты приёмами рендеринга (белым по
  белому, 1px, opacity, display:none), остальное — zero-width и Unicode-теги,
  разбивающие «триггерные» слова.
- **Индустрия признала, что не чинится изнутри.** OWASP держит prompt injection
  как **LLM01** — «архитектурная уязвимость, а не баг реализации»; успех атак в
  агентных системах доходит до **84%**; 13 февраля 2026 OpenAI выпустила
  Lockdown Mode для ChatGPT и **публично признала, что prompt injection в
  AI-браузерах «может никогда не быть полностью закрыт»**.
- **Рост вектора:** +340% г/г по OWASP-отчёту 2026; PoC Brave против Perplexity
  Comet — скрытые инструкции заставляли агента доставать OTP из почты.

Полные выкладки с источниками — [evidence/02-ai-agent-threats.md](evidence/02-ai-agent-threats.md).

Вывод: **нужен внешний, независимый от AI-провайдера щит на уровне страницы.**
Продукта для потребителя в этой нише нет ни у Guardio, ни у Aura, ни у Norton, ни
у Malwarebytes.

И вторая половина уравнения: **невидимость сама по себе — сильный сигнал**.
Текст, который есть в DOM, но не виден человеку, и при этом похож на инструкцию,
— детектируется дёшево, локально, без облака. Это ровно наш тип задачи.

## 3. Пять функций ядра (приоритет по запросу заказчика)

| # | Функция | Суть |
|---|---|---|
| **1** | **AI Shield** | Скан страницы на вшитые скрипты и команды для AI-агентов: скрытые инструкции, промпт-инъекции, ловушки для суммаризаторов. Детект + очистка + предупреждение |
| **2** | **Guard ссылок и загрузок** | Проверка URL до перехода и каждой загрузки: репутация, возраст домена, хэш файла |
| **3** | **Extension Guard** | Инвентарь расширений, риск-скоринг, дифф разрешений между версиями, смена владельца, предупреждение до установки |
| **4** | **Утёкшие пароли и данные** | Офлайн-проверка паролей по корпусу HIBP + мониторинг утечек и infostealer-логов |
| **5** | **Дружелюбный ассистент** | Объясняет простым языком, что произошло, и **чинит вместе с тобой**: пошагово, с кнопками, без паники |

### Базовый набор — полный, а не «в довесок»

AI-слой стоит **сверху** классической защиты, а не вместо неё: пользователя
по-прежнему разводят обычным фишингом. Поэтому базовый набор закрыт целиком —
детальная матрица в **[coverage-matrix.md](coverage-matrix.md)**:

фишинговые страницы логина · **typosquat / homoglyph / punycode-IDN** ·
открытые редиректы и цепочки · malvertising · скам-магазины ·
**tech-support scam** (полноэкранные локи, зацикленные диалоги) ·
**ClickFix / фейковая CAPTCHA с paste-and-run** · Browser-in-the-Browser ·
**quishing (QR)** · фейковые обновления браузера · домены-однодневки ·
подмена поисковика · спам push-уведомлений · clipboard-hijack и подмена
крипто-адреса · защита при вводе пароля и карты · вредоносные загрузки
(URL + хэш + маскировка типа) · утёкшие и переиспользованные пароли ·
infostealer-логи · полный набор проверок расширений.

## 4. Как работает каждая

### 4.1 AI Shield — главное отличие продукта

**Что ловим:**
- текст в DOM, невидимый человеку (цвет ≈ фон, `display:none`, `visibility:
  hidden`, `opacity:0`, размер ≤1px, вынос за вьюпорт, `clip`/`clip-path`);
- нерендеримые носители: HTML-комментарии, `<meta>`, `alt`, `title`,
  `aria-label`, `data-*`, JSON-LD, скрытые `<template>`;
- zero-width символы, Unicode-теги, разрывы токенов внутри «триггерных» слов;
- императивные конструкции, адресованные модели («ignore previous
  instructions», «you are now…», «send the contents of…»), в т.ч. на других
  языках;
- известные повторяющиеся шаблоны кампаний (сигнатуры).

**Как считаем — три ступени, все локально:**
1. **DOM-vs-render diff** — детерминированно, микросекунды, без модели. Даёт
   «невидимый текст есть/нет» и его объём.
2. **Правила и сигнатуры** — императивы, известные шаблоны, подозрительные
   Unicode-классы.
3. **Классификатор** — компактная модель (класс `Llama-Prompt-Guard-2-22M`,
   DeBERTa-xsmall, 22M параметров, устойчивая к атакам на токенизацию) в
   ONNX/WebGPU. Тяжёлые варианты (ProtectAI DeBERTa-v3-base 184M, ~1 ГБ + GPU)
   осознанно не берём в базовую поставку.

**Что делаем с находкой (уникальная часть):**
- **Предупреждаем**: «На этой странице спрятаны инструкции, адресованные
  AI-помощнику» + показываем сам текст и место, где он спрятан.
- **Санитайзер**: по кнопке (или автоматически в «режиме агента») удаляем
  скрытые инструкции из DOM **до** того, как их прочитает сайдбар/агент/
  суммаризатор. Это защита не только для пользователя, но и для его AI.
- **Стоп-кран на действие**: если агент собирается совершить чувствительное
  действие на странице с найденной инъекцией — требуем явного подтверждения.

### 4.2 Guard ссылок, страниц и загрузок (классический анти-скам)

- **До перехода:** локальные агрегированные фиды (OpenPhish/PhishTank/URLhaus/
  Phishing Army) + Safe Browsing Local List (только хэш-префиксы) + скоринг
  «возраст домена / CT / похожесть на бренд / есть форма пароля».
- **Обманки в самом URL — считаем локально:** декодирование punycode и
  Unicode-confusables (`аpple.com` → `xn--pple-43d.com`), typosquat-расстояние до
  Tranco и до личного списка «мои банки/биржи/почта», разворачивание открытых
  редиректов до конечного адреса.
- **Обманки на странице:** ловушки tech-support scam (насильный fullscreen,
  зацикленные диалоги, фейковый интерфейс ОС), Browser-in-the-Browser (фейковое
  окно SSO), QR-коды (показываем реальный URL до того, как его отсканирует
  телефон), фейковые страницы обновления браузера.
- **ClickFix / фейковая CAPTCHA (paste-and-run)** — вектор с ростом **+517%** за
  полугодие и кампаниями на 700+ взломанных сайтов: ловим момент, когда страница
  пишет в буфер обмена команду и просит открыть Win+R. Настоящая CAPTCHA никогда
  не просит выйти из браузера — так и говорим пользователю.
- **Защита ввода:** предупреждение до отправки формы, если пароль или карта
  вводятся на свежем/недоверенном домене; детект подмены скопированного
  крипто-адреса.
- **Загрузки:** `chrome.downloads` + `onDeterminingFilename` → проверка
  `finalUrl` по фидам, репутация источника, тип файла и «двойное расширение»,
  затем **хэш** по MalwareBazaar (бесплатный community API) и опционально
  VirusTotal (только хэш, не файл; публичный API — 500/день, 4/мин,
  non-commercial).
- **Ограничение честно:** расширение не читает файл с диска, поэтому хэш
  считается по повторно скачанным байтам и работает для прямых ссылок; для
  загрузок за авторизацией остаётся URL-репутация и эвристики. Пишем это в UI,
  а не молчим.
- **Объяснимый вердикт** + «это ошибка» в один клик с запоминанием (прямая боль
  категории — ложные срабатывания и заблокированные чужие сайты без уведомления).

### 4.3 Extension Guard — непрерывно, а не один раз при установке

Разовая проверка бесполезна: расширения с 7-летней историей доверия
превращали в шпионское ПО **тихим обновлением** (~4.3 млн устройств), а в
расширении с 900k пользователей нашли скрытую экспфильтрацию данных. Ядро риска —
изменения во времени. Полный список сигналов — в
[coverage-matrix.md](coverage-matrix.md) §3, коротко:

- инвентарь и разрешения (`chrome.management`), риск-скоринг;
- **дельта разрешений между версиями** и **смена владельца/издателя**;
- тихое обновление после долгого затишья;
- статический разбор пакета: обфускация (энтропия), `eval`/`new Function`,
  загрузка удалённого кода, внешние эндпоинты против фидов C2;
- опасные комбинации прав (`<all_urls>` + `cookies` + `scripting` + буфер);
- доступ к AI-панелям и агентским поверхностям (эскалация привилегий через
  Gemini-панель — CVE-2026-0628);
- установка вне стора (`installType`);
- предупреждение **до** установки прямо на странице Web Store;
- действие в один клик: выключить, взять под наблюдение, добавить в доверенные.

### 4.4 Утёкшие пароли и данные

- **Пароли — офлайн**: локальный корпус Pwned Passwords, ноль сетевых запросов;
  при отказе от полного корпуса — k-anonymity (5-символьный префикс SHA-1 +
  `Add-Padding`).
- **Утечки**: HIBP (метаданные + email) + XposedOrNot + **Hudson Rock Cavalier**
  (infostealer-логи, бесплатно, без ключа) — это тот класс данных, из-за
  которого одни сервисы находят 18 утечек, а другие 8.
- Теги скомпрометированных данных, архив разобранного, diff «что нового за
  неделю».

### 4.5 Дружелюбный ассистент

Не чат-бот ради чат-бота, а **проводник по починке**.

- **Всегда объясняет причину**: почему заблокировано / что именно нашли / чем
  это грозит — человеческим языком, без жаргона и без запугивания.
- **Даёт конкретный следующий шаг** и делает его сам, где может: выключить
  расширение, открыть `/.well-known/change-password`, найти повторное
  использование пароля, удалить скрытые инструкции со страницы, добавить
  исключение, отозвать доступ.
- **Очередь из трёх дел** вместо списка на 203 строки.
- **Деградация по возможностям устройства:** детерминированные плейбуки →
  компактная локальная модель → **Chrome Built-in AI (Gemini Nano,
  `LanguageModel`/`Summarizer`, полностью на устройстве)**, если доступен →
  опционально собственный API-ключ пользователя. По умолчанию **содержимое
  страницы наружу не уходит никогда**; облако — только явный опт-ин.
- Тон: спокойный ассистент, а не сирена. Метрика — «доля алертов, доведённых до
  действия», а не «сколько угроз показано».

**Чем принципиально отличается от Norton Genie / Bitdefender Scamio / McAfee /
Trend Micro ScamCheck:** все четыре — **реактивные**. Они срабатывают, только
если человек уже заподозрил неладное и сам пошёл спросить. В независимом тесте
2026 года ни один не набрал идеального результата, все испытывали проблемы с
изображениями, а скриншоты подвешивали приложения
([evidence/06](evidence/06-competitors.md) §6.2).

Наш ассистент **проактивен и привязан к моменту события** — странице, загрузке,
установке расширения, найденной утечке. Плюс два режима, которых нет у них:

- **«Посмотри вот это»** — можно принести подозрительное сообщение, письмо или
  **скриншот**; разбор идёт локально (OCR + правила + модель), а не в облаке
  вендора.
- **«Я уже попался»** — план восстановления: что менять в первую очередь, где
  отозвать сессии, что проверить на переиспользование, за чем следить дальше.
  По опросу Iris ICC 2026 **57%** глубоко обеспокоены скамом, но лишь **14%**
  имеют доступ к разбору и поддержке — это и есть незакрытая ниша
  ([evidence/05](evidence/05-demand-and-market.md) §5.6).

### 4.6 Бесплатный вход: «проверь себя»

Данные по спросу однозначны: запрос `have i been pwned` — **165 000/мес** в США
и **74 000/мес** в UK, а сам сайт даёт **515 184** органических визита в месяц
при 4 054 ключах. Это на порядок больше любого запроса вида «купи защиту»
([evidence/05](evidence/05-demand-and-market.md) §5.1, §5.4).

Вывод для продукта: **точка входа — не «поставь и подпишись», а «проверь себя за
5 секунд»**. Первый экран после установки — мгновенная локальная проверка:
утёкшие пароли, рискованные расширения, страницы со скрытыми инструкциями в
текущих вкладках. Ценность до первого клика по настройкам.

Подтверждение форм-фактора: **80%** опрошенных использовали бы защиту,
встроенную в то, чем уже пользуются, и вдвое чаще предпочитают встроенный опыт
(38%) отдельному сайту или приложению (18%). Браузерное расширение — ровно этот
формат.

## 8. Анти-цели

- Не антивирус файловой системы и не лечение заражённого устройства.
- Не кредитный мониторинг и не страховка (финансовый продукт, привязан к США).
- Не подписка-ловушка, не заблюренные фичи ради апсейла.
- Не хостим и не перепродаём чужие дампы.
- Не отправляем содержимое страниц в облако «для анализа» — даже своё.
- Не соревнуемся с бесплатными блокировщиками рекламы.

## 9. Риски и гашение

| Риск | Гашение |
|---|---|
| Гонка вооружений: обфускация инъекций | три независимые ступени детекта; сигнатуры обновляются как фид; невидимость как инвариант — её нельзя убрать, не показав текст человеку |
| Ложные срабатывания на легитимном скрытом тексте (a11y, SEO-разметка) | вес по «императивности» + адресность модели; аллоулист; обжалование в один клик; публичная проверка статуса домена |
| Chrome Built-in AI требует ~22 ГБ диска и 4 ГБ VRAM, доступен в расширениях через origin trial | ассистент работает без него (плейбуки + компактная ONNX-модель); Nano — усиление, не зависимость |
| Лимиты MV3 (330k статических / 30k динамических правил) | статический пакет + горячая динамика + локальные хэши в SW; бюджет считаем в спеке |
| Safe Browsing v5 — только non-commercial; VT public API — non-commercial | при коммерциализации переход на Web Risk; источники сменные по интерфейсу |
| Лицензии фидов (HIBP CC BY 4.0) | атрибуция в UI и доках |
| Расширение не читает файл с диска | честный UI об охвате; хэш по повторно скачанным байтам + URL-репутация |

## 10. Решения (закрыты 2026-08-04)

Развилки закрыты на брейншторме и intake-грилле; детали — в

   отпал, потому что публичная страница статуса домена и приём апелляций
   требуют серверной стороны.
2. **Q2:** **код открыт, пользоваться бесплатно**; с 2026-09-30 — под лицензией
   организации: GNU AGPL-3.0 или коммерческая лицензия для использования вне
   условий AGPL, по договорённости (ADR-0016; до этого PolyForm, ADR-0015).
   Монетизации нет — значит нет пейволов, триалов и flow отмены подписки.
3. **Q3:** нулевой бюджет фидов на старте; платные — точечно, «по требованию».
4. **Q5:** Chrome + Edge + **Firefox** из одного браузеро-независимого ядра.
5. **Q6:** почта отложена в carry-over.
6. **Q7:** локальное хранилище, без шифрования-театра; способ поставки корпуса
   паролей решается замером в спеке.

## 11. Позиционирование

> Твой браузер теперь читает не только ты — его читает твой AI.
> И на страницах уже лежат инструкции, написанные для него, а не для тебя.
>
> **Okolos находит их раньше, чем их прочитает агент — и вычищает.**
> Плюс проверка ссылок и загрузок, контроль расширений, утёкшие пароли офлайн —
> и спокойный ассистент, который не пугает цифрами, а доводит до починки.
> Всё считается у тебя на устройстве. Каждый исходящий запрос виден в панели
> самоаудита.
