# ADR-0018. У агентов — своё расширение, Okolos Bridge, в этом же репозитории

**Дата:** 2026-10-05
**Статус:** принято оператором 2026-10-05: «да, два расширения получается: Okolos — люди, Okolos
Bridge — агенты, всё это внутри одного нашего проекта».
**Основание:** отчёт `okolos/2026-10-05-agent-browser-bridge` (база знаний продукта, вне этого репозитория), §9.1 и «архитектура, L3».

## Контекст

Okolos должен стать дверью, через которую любой локальный агент входит в браузер человека, и щитом в
этой двери: очищенный снимок страницы, закрытый набор глаголов, лестница автономии. Доверенный ввод и
снимок дерева доступности дают только `chrome.debugger`. Три факта платформы, проверенные 2026-10-05:

- `debugger` **не может быть необязательным разрешением**. Добавить его в установленное расширение —
  значит показать каждому пользователю «читать и изменять все ваши данные» и запрос на повышение прав.
  Для продукта безопасности хуже сигнала нет.
- Правило единственного назначения в Chrome Web Store и Edge, и правило AMO «несвязанное — только
  opt-in». Защита человека и пульт для агента — два назначения.
- С Chrome 155 (стабильный 2026-10-06) `attach()` падает в управляемых браузерах с
  `runtime_blocked_hosts`, `DisableScreenshots` или DLP. Корпоративный пользователь не должен терять
  защиту из-за того, что мост там не работает.

## Решение

- **Два расширения.**
  - **Okolos** — для людей, с нынешним набором прав.
  - **Okolos Bridge** — для агентов: `debugger`, native messaging, группы вкладок, side panel.
- **Один репозиторий и общие пакеты.** `core-*`, `contracts`, `net`, `i18n`, `ui`. Bridge — новое
  приложение рядом с `apps/extension`, а не форк.
- **Расширения не разговаривают друг с другом напрямую.** Оба ходят к локальному Okolos Agent.
  `externally_connectable` нет ни у одного: этим каналом прошёл ClaudeBleed (любое расширение
  управляло Claude in Chrome через его `externally_connectable`).

## Цена

- **Два листинга в каждом магазине, два ревью и два обновления.** Ревью Bridge с `debugger` займёт
  недели.
- **Человек ставит второе расширение**, чтобы пустить агента. Это шаг установки, но он же и согласие:
  без Bridge агент в браузер не входит.
- **Защита человека в Okolos не знает о задачах агента напрямую.** Всё, что им нужно друг о друге,
  идёт через Okolos Agent, а его нужно построить (Б1).

## Чем держится

| Часть | Механизм |
|---|---|
| В манифестах Okolos нет `debugger`, `nativeMessaging`, `tabGroups`, `sidePanel`, `history`, `bookmarks` — ни в обязательных, ни в необязательных правах — и нет ключей `externally_connectable`, `side_panel` | `tools/manifest.test.ts` — «the line between Okolos and Okolos Bridge (ADR-0018)» |
| Проверка не слепая: искусственный манифест с этими правами она ловит | там же — «would notice the bridge creeping in» |
| Права Okolos не растут молча вообще | `tools/manifest.test.ts` — «requests only the permissions the skeleton needs» |

Когда появится приложение моста, в эту таблицу добавятся проверки его манифеста: что в нём есть, что
`externally_connectable` пуст, что `allowed_origins` native host перечисляет точные ID.
