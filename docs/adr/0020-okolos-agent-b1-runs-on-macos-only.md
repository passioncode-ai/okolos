# ADR-0020. Okolos Agent фазы Б1 работает только на macOS; Windows отдельной фазой

**Дата:** 2026-10-27
**Статус:** принято агентом прогона 2026-10-27 по правилу оператора «открытый вопрос: это решение»
(выбрана самая обратимая возможность); оператор может пересмотреть. Записано в этом дереве 2026-10-29.
**Основание:** аудит стабильности и Windows 2026-10-27 (строка B-167), бриф моста Б1 на ветке
`bridge/b1-run2`, коммит `4de1dff`, раздел «Не входит».

## Контекст

Демон Okolos Agent (мост, фаза Б1) кладёт данные, логи и кэш в `~/Library` (`serviceDirs` в файле
сервиса `dirs.ts` на ветке `bridge/b1-run2`), запускается через launchd и хранит ключи в связке
`security`. Ни один из трёх механизмов не существует на Windows. До этой записи решение нигде не
было принято: README и facts.md не обещали Windows для моста, но и не исключали её (B-167).

## Решение

- Б1 ставится и работает только на macOS.
- Windows для Okolos Agent идёт отдельной фазой, строка B-171: каталоги по разметке Windows, служба
  или задача планировщика вместо launchd, хранилище ключей Windows вместо `security`.
- Linux в Б1 тоже не входит; отдельной строки пока нет, потому что спроса на него не записано.
- Расширение Okolos этим решением не затронуто: оно работает на Windows, macOS и Linux (B-166).

## Цена

Человек на Windows не может подключить своего агента к браузеру через Okolos Agent, пока не сделана
фаза B-171. Код демона на macOS пишется без слоя переносимости, поэтому фаза Windows потребует
выделить его из `dirs.ts`, из установки launchd и из работы с ключами.

## Чем держится

- Строка «Okolos Agent (мост, фаза Б1)» в `docs/brand/facts.md`, раздел «Где работает», и строка
  в таблице ОС `docs/runbooks/development.md`: обе говорят «только macOS» и ссылаются сюда.
- Строка B-171 в `docs/backlog.md`: открытая работа, без которой Windows не обещается.
- Сам демон пока не влит в main; когда он вольётся, это решение держит его код каталогов
  (`~/Library`) и установка через launchd.
