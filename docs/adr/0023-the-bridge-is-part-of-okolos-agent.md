# ADR-0023. Мост для агентов (Okolos Bridge) живёт в Okolos Agent: две двери, задача в своём окне

**Дата:** 2026-11-19
**Статус:** принято агентом по делегированию оператора (правила «полная делегация», 2026-11-05 и
2026-11-08); построено на ветке `bridge/b1-next` (K3, B-142).
**Основание:** спека Б1 `docs/superpowers/specs/2026-10-06-bridge-b1-design.md`, план
`docs/superpowers/plans/2026-10-27-bridge-b1.md` (REQ-67), правило оператора 2026-11-18 «у MCP две двери:
`search` и `execute`».

## Контекст

Агенту, который работает за человека в браузере, нужна дверь, через которую он видит страницу так, как
её видит человек: без текста, который страница спрятала от людей. Расширение Okolos не может быть этой
дверью: в нём нет `nativeMessaging` и `externally_connectable` (ADR-0018), и в Б1 у него нет канала к
демону. Значит, дверь держит отдельная служба на машине человека.

## Решение

1. **Мост живёт в Okolos Agent**, локальном демоне `fabric-service/0.1` (`apps/agent`), а не в
   расширении и не в облаке. Страница никогда не уходит с машины (ADR-0019).
2. **Две двери на одном порту `127.0.0.1:47871`.** Для агента: MCP Streamable HTTP `/mcp` ровно с двумя
   инструментами, `search` (операции с назначением, схемой, воротами и примером) и `execute` (операция
   по имени), плюс `/pair`, `/pair/claim`, `/pair/release` для привязки. Для человека: страница
   `/dashboard` и её `/api` в Fabric Dashboards, по сессии от кода входа. Дверь агента отвергает любой
   `Origin` и любой заголовок `Sec-Fetch-*`, который шлёт только браузер: веб-страница клиентом двери
   не бывает.
3. **Доступ даёт человек, по коду.** Агент просит доступ командой `okolos-agent pair`, видит шестизначный
   код; человек сверяет тот же код на странице и подтверждает. Ключ выдаётся агенту один раз, демон
   хранит только его SHA-256. Подтвердить можно только на странице, по метке строки, а не по
   идентификатору запроса, который держит агент: агент не может привязать сам себя.
4. **Задача: своё окно.** Каждая задача агента открывает своё окно в Chrome stable человека, на своём
   профиле агентов (`agent`, общий для агентов с доступом) или на временном контексте (`disposable`),
   в фоне: приложение человека остаётся впереди, полосы «управляется автоматизацией» нет, потому что
   `--enable-automation` не передаётся никогда.
5. **Агент получает только очищенное.** Каждый текст страницы, который получает агент, строится из
   строк очищенного снимка (ADR-0024): пробник расширения в изолированном мире называет скрытое, снимок
   вырезает его с потомками и маскирует значения полей. Ответ агенту уходит только после записи в
   журнал агентов.

## Граница угроз Б1

- **Клиент с оболочкой на этой машине и есть код от имени человека.** Агент-программист с доступом к
  оболочке, которым управляет инъекция со страницы, может прочитать токен хоста, открыть страницу
  `/dashboard` и прочитать профиль Chrome, как может любой процесс человека. В Б1 от этого пути
  защищает только очистка снимка: агент, который читает страницы через мост, не видит текста, которым
  страница могла бы им управлять. Подтверждение по Touch ID запланировано на Б2.
- **Loopback не значит человек.** Каждая утечка мостов 2025–2026 годов, найденная в исследовании, шла
  через дверь, которая верила, что локальный вызов делает человек. Здесь вызов без ключа отвергается,
  а ключ даёт только человек на странице.
- **Расширение Okolos в Б1 не имеет канала к демону.** Как они встретятся, решается в Б2 вместе с
  дверью для действий расширения (ADR-0022).

## Цена

- Человек ставит и держит ещё одну службу (launchd, `okolos-agent doctor`), и у агентов свой Chrome на
  его машине: окно, процессы, профиль на диске.
- Агенту, у которого есть оболочка, мост в Б1 не мешает обойти себя; он защищает только то, что агент
  читает через него.
- Б1 работает только на macOS (ADR-0020).
